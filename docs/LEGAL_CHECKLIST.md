# 출시 전 법무·데이터 체크리스트

상태: 출시 차단 목록  
기준일: 2026-08-15

법률 자문서가 아니다. 면책문구만으로 인가·등록·소비자보호·개인정보 의무가 사라지지 않는다. 한국 변호사와 데이터 권리 담당자가 출시 모델, 실제 화면, 약관, 광고를 함께 검토한다.

## 1. 금융 규제

- [ ] 신호 생성, push, 전략 복사, 공개 랭킹이 투자자문업 또는 유사투자자문업에 해당하는지 의견서 확보
- [ ] 개인 맞춤성 판단 요소: 사용자 보유, 위험 성향, 종목 범위, 알림 문구, 유료화, 사람 개입
- [ ] `사용자 설정 조건 충족 신호`가 실제 UX에서도 추천·권유로 오인되지 않는지 검토
- [ ] 전략 공개·복사, 지표 tier, 상위 조합이 특정 종목 매매 권유로 보이는지 검토
- [ ] 자동 실주문이 모든 앱·API·약관·권한 scope에서 빠졌는지 확인
- [ ] 향후 증권사 주문·계좌 연동 전 금융투자업, 전자금융, 신용정보 범위 재검토
- [ ] 고객 문의·운영자 메시지가 개별 자문으로 바뀌지 않도록 응대 지침 작성
- [ ] 금융위원회·금융감독원 사전 질의 또는 규제 샌드박스 필요성 검토

## 2. 성과·광고·표시

- [ ] `매수 추천`, `즉시 매도`, `손실 방지 보장`, `수익 보장` 금칙어 검사
- [ ] 백테스트·페이퍼·수동 실제 기록을 뚜렷하게 구분
- [ ] 비용, spread, slippage, 세금, benchmark, 기간, 표본 수, 산식 버전 표시
- [ ] 생존자 편향, 미래 데이터, 현재 지수 구성 소급 금지 검증
- [ ] `데이터 부족` 기준 30 신호와 신뢰구간 표시
- [ ] 사용자 순위가 종목군 보정 없는 순수익률임을 화면에 고지
- [ ] 열린 손실을 NAV에 포함. 중도 시작 사용자를 정규 기간 순위에서 제외
- [ ] 체리피킹, 손실 트랙 삭제, 결과 확인 뒤 우선순위 변경 금지
- [ ] influencer, 리뷰, 추천인, 보상 공개 정책 검토
- [ ] 앱스토어 설명, screenshot, push 문구도 같은 기준으로 법무 검수

필수 고지 초안:

`본 앱의 신호, 랭킹, 백테스트는 정보·교육 목적의 기계적 산출물입니다. 투자자문 또는 수익 보장이 아닙니다. 백테스트와 페이퍼 성과는 미래 성과를 보장하지 않습니다. 비용, 데이터 지연, 시장 상황으로 실제 결과가 달라질 수 있습니다.`

## 3. 공개 전략·프로필

- [ ] 공개 동의 기본 false, 항목별 범위와 철회 효과 명시
- [ ] 전략 파라미터 공개가 저작권·영업비밀·부정경쟁 쟁점을 만드는지 검토
- [ ] 닉네임 사칭, 명예훼손, 시세조종성 게시, 신고·차단 처리 절차
- [ ] 완료 execution과 1거래일 지연 열린 position 정책 고지
- [ ] 공개 철회 즉시 신규 view·랭킹에서 제거
- [ ] 감사 원장 보존 기간과 공개 삭제를 분리
- [ ] 기록 세탁 방지를 위한 옛 트랙 공개·보존 정책과 이용자 동의
- [ ] 타인 전략 복사 시 출처·라이선스·삭제 뒤 파생 전략 처리 정책

## 4. 개인정보

- [ ] 처리 목적, 항목, 법적 근거, 보유 기간을 기능별 data map으로 작성
- [ ] 이메일, 닉네임, device token, 알림 설정, IP·로그, 신고 자료 분류
- [ ] 실제 보유·체결 메모에 민감 정보가 입력될 가능성과 최소 수집 조치
- [ ] 공개 정보와 내부 user UUID 분리. 이메일·실제 투자금·MANUAL_LIVE 비공개
- [ ] 개인정보 처리방침, 이용약관, 동의 화면을 앱에서 쉽게 접근 가능하게 제공
- [ ] 수탁자, cloud region, 국외 이전 국가·시점·방법·보유 기간 확정
- [ ] 분석·crash·push SDK별 수집 항목과 opt-out 확인
- [ ] 열람, 정정, 삭제, 처리정지, 동의 철회 접수·본인 확인·기한 절차
- [ ] 계정 삭제 시 즉시 세션 폐기·공개 철회·비동기 삭제 상태 제공
- [ ] 법정 보존과 사용자 삭제 요청 충돌 시 항목별 근거·기간 기록
- [ ] 14세 미만 허용 여부 결정. 허용 시 법정대리인 절차 구현
- [ ] 개인정보 보호책임자, 침해 대응, 유출 통지, 증적 보존 담당 지정
- [ ] encryption, access review, RLS test, secret rotation, backup 삭제 검증

개인정보보호위원회는 처리방침에 처리 절차·기준과 권리 보장 내용을 투명하게 쓰도록 안내한다. 출시 시점 최신 [개인정보 처리방침 작성지침 목록](https://m.pipc.go.kr/np/cop/bbs/selectBoardList.do?bbsId=BS217&mCode=D010030000)을 다시 확인한다.

## 5. 시세·데이터 라이선스

- [ ] 증권사 API 이용료와 KRX 시세 정보 이용료를 분리 견적
- [ ] 실시간·지연·EOD·과거 데이터별 이용권 분리 확인
- [ ] 원시 데이터 저장 기간과 cache 허용 범위
- [ ] candle 생성, 수정주가, 지표, 신호, 랭킹이 허용된 가공물인지 서면 확인
- [ ] 앱 화면, push, 공개 프로필, API에서 재배포 가능 범위
- [ ] 사용자 수, 기기 수, 동시 접속, 외부 노출별 fee
- [ ] index 구성 이력, corporate action, 종목 master의 출처·권리
- [ ] provider 종료·계약 해지 때 삭제·반환 의무
- [ ] 출처 표시, 지연 시간 표시, 면책 표시 형식
- [ ] primary·fallback source 혼합과 파생 데이터 권리

KRX OPEN API도 활용 신청과 이용 조건 확인이 필요하다. [KRX Data Marketplace 이용방법](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO003.jsp)을 시작점으로 쓰고 계약 담당자 답변을 보관한다.

## 6. 유료화 전

- [ ] 현재 free plan 전체 권한 확인. 결제 SDK·페이월 없음
- [ ] 유료 신호·랭킹·알림이 금융 규제 분류를 바꾸는지 재검토
- [ ] 가격, 자동 갱신, 청약철회, 환불, 해지, 세금, 영수증 정책
- [ ] Apple·Google 인앱결제와 금융 서비스 정책
- [ ] 전자상거래 소비자 보호, 표시·광고, 약관 심사
- [ ] 무료 체험과 유료 전환 동의 증적

## 7. 보안·운영

- [ ] service role, broker key, push token이 모바일·repo·log에 없음
- [ ] API auth, ownership, RLS, rate limit, idempotency 침투 테스트
- [ ] 공개 safe view 열 목록과 우회 query test
- [ ] 잠금 화면 push에 수량·평단·수익 등 민감값 최소화
- [ ] 관리자 접근 사유·승인·감사·정기 review
- [ ] backup, restore, 삭제 전파, incident drill
- [ ] dependency·container·secret scan과 대응 SLA
- [ ] 신고, 차단, 악용, 조작, 봇 계정 운영 정책

## 8. 출시 승인 증적

- [ ] 법무 의견서 버전과 승인자
- [ ] 시세·API 계약서, 주문서, 권리 행렬
- [ ] 개인정보 data map, 처리방침, 수탁자·국외이전 목록
- [ ] 실제 화면·push·스토어 문구 승인본
- [ ] 산식·비용·fill 모델 버전과 독립 재현 결과
- [ ] 보안·RLS·삭제·복구 테스트 결과
- [ ] 미해결 위험의 책임자·기한·출시 차단 여부
